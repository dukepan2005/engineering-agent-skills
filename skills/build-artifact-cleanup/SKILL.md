# Build Artifact Cleanup

Use `scripts/cleanup-build-artifacts.sh` from this skill. With no explicit targets, it discovers the supported FlowCoach iOS and Go artifacts. For another project or a nonstandard artifact, use explicit mode: pass `--root <workspace>` and select exact workspace paths with `--target <relative-path>` or exact temporary paths with `--temp-target <absolute-path>`. Combine the flags in one preview. Temporary targets must be owned by the current user and lie below `/private/tmp` or the active macOS temporary directory. Add `--preserve <path>` for source or other content that must remain. Use a project subdirectory as the workspace root. Explicit mode rejects traversal, symlinked targets and parents, overlapping targets, and targets that overlap preserved paths. It does not infer artifact names or scan unrelated files.

## Safety gate

The skill invocation and requests such as “clean”, “cleanup”, “清理”, or “cache” authorize inventory only. Start by running the script without `--apply`, then show the user every full target path and its size in MB/GB, rounded to two decimal places (decimal units: 1 GB = 1,000 MB), plus the approval token. Stop there and wait for separate, explicit approval of that exact list. Only then run `--apply --approval-token <token>` with the token from that preview. A request made before seeing the inventory does not approve later-discovered targets. In explicit mode, apply removes approved paths that still match the preview and prints a fresh preview, token, and retry command for changed paths only. Report the partial result and ask for approval of the changed paths. A missing path is already absent. A safety check failure still stops cleanup. The default discovery mode requires fresh approval of its entire inventory when it changes.

The script fails closed if process inspection fails and rechecks the approved inventory and process state immediately before deletion. Default FlowCoach mode checks for active build/test processes. Explicit mode checks build/test command lines that reference the selected workspace and checks whether any process has files open in the selected targets. If the environment blocks the process check and the user has explicitly asked to resolve the restriction and continue, retry the exact same script invocation once with the approved inventory token through the environment's approval-gated elevated execution. The script repeats all checks before deleting. If that execution is rejected or process inspection still fails, stop and report it; do not bypass the script or use a separate deletion command. If deletion itself fails because of filesystem permissions, stop and report the result.

The default inventory includes the shared `XcodeBuildMCP/workspaces` and `XCTestDevices` directories, so the user can approve their scope explicitly. After successful cleanup and verification, report the pre-clean disk usage removed for iOS, Go, and explicit targets separately, plus the combined total.

This script does not delete Simulator devices. If a separately authorized cleanup removes devices by name, preview exact names, runtimes, states, and UUIDs from fresh `xcrun simctl list devices --json` output and get approval. After approval, query the JSON again immediately before deletion; resolve the names again, require the approved runtime and UUID to match, and derive the deletion UUIDs from that fresh result. If the inventory changed, stop and request approval for a refreshed list. Delete only devices in the Shutdown state; refuse Booted or any other state. Query the device list again after deletion and verify the approved UUIDs are absent. Never reuse UUIDs copied from an older command output or conversation.

The script retains reusable dependency caches, including the Go module download cache in default mode. In explicit mode, select only disposable output and use `--preserve` to protect reusable workspace caches. It also retains the default global `$HOME/Library/Caches/go-build` cache unless the user explicitly includes it; only then pass `--include-go-cache` in both preview and apply. Other configured Go build caches remain in the preview. It scans `*go-build*`, `*gocache*`, and `*go-cache*` under `TMPDIR`, `GOTMPDIR`, and `/private/tmp`. Matching build/test cache paths are deleted even when their names contain a work-item ID; unrelated source files remain outside the cleanup targets.

Keep this skill as the single source for this cleanup behavior. Do not add a second copy of its cleanup script or rules to a component repository.
